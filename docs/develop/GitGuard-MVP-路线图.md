# GitGuard — 推送二次确认 MVP 路线图

> 本文是该阶段唯一的路线图与范围声明。安全边界以 [SECURITY.md](../SECURITY.md) 为准，依赖方向与链路细节以 [ARCHITECTURE.md](../ARCHITECTURE.md) 为准，界面结构以 [桌面端信息架构与交互设计](GitGuard-桌面端-信息架构与交互设计.md) 为准。本文与代码冲突时以代码为准，并顺手修正文档。

## 1. 定位与防护边界

- **目标**：在数据发出前让用户核对本次推送的目标与提交，降低误推、错推风险；本地优先，无云端业务后端、无遥测、无后台常驻进程。
- **拦截点**：Git 原生 `pre-push` Hook。push 可能来自终端、IDE、图形客户端等任意位置，只在应用界面里提供一个「推送」按钮无法覆盖，因此拦截必须落在 Git 执行链路里。
- **定位是「防误推」而非「防本机恶意用户」**：客户端 Hook 可被 `--no-verify`、删改 Hook、修改 Git 配置绕过；GitGuard 不替代服务端分支保护或组织级强制审批。
- **平台**：当前仅 macOS / Linux（IPC 依赖 Unix Domain Socket，Hook 脚本依赖 POSIX shell）。

## 2. 现状

### 2.1 已实现

- **Hook**：`pre-push` 安装 / 卸载 / 健康检查；外来 Hook 备份为 `pre-push.gitguard-backup` 并链式调用，CLI 拒绝时不会绕到被备份的 Hook。
- **CLI**（`gitguard`）：参数校验、完整读取 stdin、逐行解析四字段 ref、选择确认通道、确认后重新校验 ref、稳定退出码映射；`--policy` 仅用于原型调试，不读配置、不发 IPC。
- **确认通道**：stdout/stderr 至少一个是终端且 `/dev/tty` 可打开时走终端确认（分页、`y`/`yes`）；否则经 Unix Domain Socket 请求桌面端确认。
- **桌面端**：待确认请求列表、提交预览、手输 `yes`；确认前后均重新校验 ref，只回 `Confirmed`，不执行任何 Git 命令。
- **配置**：本地 JSON（全局未登记仓库默认值、仓库登记与开关、Hook 状态、确认超时），原子写入，损坏或版本不认识时不覆盖。
- **界面**：总览 / 身份 / 仓库 / 策略 / 推送确认 / 日志 / 设置七个视图，侧边栏折叠、原生菜单与 `⌘,` / `Ctrl+,`、`zh-CN` / `en-US` 全量文案。
- **测试**：Rust 单元测试覆盖策略、解析、退出码、配置、Hook 生命周期、IPC 与桌面端命令；Unix 集成测试在临时仓库与本地 bare remote 间真实执行 `git push`，拒绝路径断言远端 ref 未变化；前端 Vitest + jsdom。

### 2.2 未实现（不得在 README、UI、文档中描述为已具备）

SQLite 与数据模型、身份 / remote 管理、正式策略配置与优先级计算、一次性批准之外的授权模型、Hook 升级与完整性校验、系统凭据库、日志脱敏与审计、Windows 实现、三平台真实环境验收。

### 2.3 已冻结的取舍

| 决策       | 结论                                              | 原因                                                                          |
| ---------- | ------------------------------------------------- | ----------------------------------------------------------------------------- |
| 确认后执行 | 不代执行 push；CLI 退出码 0，由原 `git push` 推送 | 避免递归调用与重复推送，也避免「还原参数」时静默丢掉 `--force`、多 ref 等语义 |
| 请求授权   | 一次性 `request_id`，取出即消费                   | 不产生可复用授权；旧请求不能授权新请求                                        |
| 数据存储   | 本地 JSON                                         | 当前数据量小；引入数据库必须同时定义迁移、失败与备份语义，属于独立里程碑      |
| 前端栈     | Element Plus 2 + Tailwind 4，无路由库 / 状态库    | 单窗口视图切换足够；少一处承载安全判断的落点                                  |
| 确认通道   | 按运行环境自动选择，不可配置                      | 通道不可配置，用户无法把确认「关小」到看不见的地方                            |
| Hook 冲突  | 不静默覆盖，只备份 + 链式调用                     | 用户已有 Hook 可能承担其它职责，覆盖即破坏用户配置                            |

## 3. 设计约束（长期有效）

1. **fail-closed**：未知、非法或不可判断一律非零退出；只有显式 `Decision::Allow`，或「用户确认 + ref 重新校验通过」映射为 0。
2. **放行只来自 Rust / CLI**：界面状态、隐藏按钮、快捷键、菜单都不构成安全控制。
3. **推送只发生一次**：确认通过后 GitGuard 不再执行 Git 命令。
4. **不拼 shell**：调用 Git 一律用 `Command` 参数数组；外部输入先校验再传给 Git。
5. **保护范围以登记为准**：已登记仓库只看自己的开关；未登记仓库回落到全局默认值。

### 3.1 Hook 相关场景

| 场景                      | 处理方式                                                        |
| ------------------------- | --------------------------------------------------------------- |
| 仓库没有 `pre-push`       | 直接安装 GitGuard Hook                                          |
| 仓库已有外来 `pre-push`   | 备份为 `pre-push.gitguard-backup`，写链式脚本；备份已存在则拒绝 |
| 已配置 `core.hooksPath`   | 通过 `git rev-parse --git-path hooks` 解析，尊重用户设置        |
| Hook 文件被删除或修改     | 健康检查显示 `Missing` / `Modified` / `Conflict`，不视为正常    |
| `git push --no-verify`    | 原生 Hook 无法拦截，明确列为安全边界                            |
| 桌面端未运行 / IPC 不可用 | 无控制终端时退出码 7，远端不变                                  |

### 3.2 输入解析边界

- 一次 push 可能更新多个 ref，必须全部解析，不能只看第一行。
- 新建分支（远端 OID 全零）、删除远端分支、强制更新要分别识别并单独展示风险。
- 解析失败、提交范围不完整、对象缺失时拒绝放行，不得用不完整列表暗示信息完整。
- 无法安全还原的参数组合（如 `--mirror`、复杂 `--force-with-lease`、无法解析的 push options）保留为待支持项，不静默降级为参数不同的推送。

## 4. 里程碑

> 已完成项用 `[x]` 标记；未完成项按顺序推进，前一个里程碑的安全项未通过不进入下一个。

### M1 工程底座与拦截证明（已完成）

- [x] Rust workspace、Vue / Vite / Tauri 工程、CI、格式化与测试。
- [x] `gitguard-core` / `gitguard-policy` / `gitguard-cli` 与统一决策、错误、退出码。
- [x] 临时仓库 + 本地 bare remote 的真实 Hook 集成测试。

**验收**：Hook 返回非零时 push 确实被阻止，拒绝后远端 ref 未变化。

### M2 确认链路（已完成）

- [x] 终端确认通道（`/dev/tty`、分页、过滤控制字符与 ANSI、URL 凭据脱敏）。
- [x] Unix Domain Socket IPC（`0600`、超时、消息上限）。
- [x] 桌面端待确认请求、提交预览、手输 `yes`、确认后重新校验 ref。
- [x] 仓库登记、Hook 安装、保护开关、确认超时。

**验收**：批准才继续；取消、超时、IPC 失败、`request_id` 不匹配均阻止 push。

### M3 界面信息架构（已完成）

- [x] 七个视图、侧边栏折叠、公共展示组件、i18n、原生菜单与设置快捷键。
- [x] 身份与日志页面按「规划中」呈现，不展示伪造数据。

**验收**：导航与语言切换只影响展示，不改变任何放行决定。

### M4 可诊断性与审计（下一步）

- [ ] 审计事件：请求创建、确认、取消、超时、失败与结果，含时间、仓库标识、remote、`request_id`、原因码。
- [ ] 定义保留与清理策略；审计写入失败只记录错误，不得让放行判断静默降级。
- [ ] 日志脱敏规则（Token、私钥、含密码的 URL、完整环境变量）。
- [ ] 错误码到用户提示与排查建议的映射；「复制诊断摘要」与导出，默认脱敏。
- [ ] 审计页面替换现有占位页。

**验收**：审计与诊断输出不含凭据；任何页面内容不被描述为审计凭证，除非审计能力已落地。

### M5 身份与策略优先级

- [ ] 提交身份管理（`user.name` / `user.email`，与 SSH/HTTPS 认证身份严格区分）。
- [ ] remote 管理与名称 / URL 变更后的失效处理。
- [ ] 正式策略配置与优先级：紧急禁用 → 显式禁止 → 高风险强制确认 → 仓库 / 身份 / 分支规则 → 明确允许 → 全局默认。
- [ ] 冲突按 `Deny > RequireConfirmation > Allow` 处理，输出稳定原因码。
- [ ] 用真实页面替换「规划中」占位，并同步 `AGENTS.md` 与架构文档。

**验收**：策略模块可独立测试；无法判断时不返回 `Allow`。

### M6 Hook 升级与完整性

- [ ] Hook 脚本版本标记与内容校验，能检测被篡改或版本落后。
- [ ] 升级 / 修复流程，升级前保留备份与校验信息。
- [ ] 卸载前确认 Hook 仍由 GitGuard 管理，不一致时拒绝删除。

**验收**：篡改可检测；卸载不会删除用户自己维护的 Hook。

### M7 Git 边界与异常时序

- [ ] 多 push URL、`pushurl`、URL rewrite、直接 URL、`core.hooksPath` 指向共享目录。
- [ ] worktree、detached HEAD、仓库移动 / 重命名 / 删除、浅克隆。
- [ ] 多仓库并发推送、桌面端崩溃与重启、系统休眠后的请求回收。

**验收**：无法安全判断时拒绝，且远端 ref 未变化。

### M8 Windows 与三平台验收

- [ ] Windows 命名管道实现与 Hook 可执行入口（`.cmd` / shell 差异）。
- [ ] 三个平台各自完成安装、升级、卸载与真实 push 流程记录，不互相代替。
- [ ] 签名、公证与分发包格式。

**验收**：每个平台有独立验收记录，未覆盖项明确列为限制。

### M9 发布候选

- [ ] 版本号、构建元数据、SHA-256 校验值。
- [ ] 安装、升级、卸载与 Hook 恢复说明；已知问题清单；发布清单。

**验收**：干净环境按文档可完成安装与核心流程，失败路径仍不放行。

## 5. 测试矩阵

| 类别       | 场景                             | 期望结果                           |
| ---------- | -------------------------------- | ---------------------------------- |
| 基础推送   | 单分支正常推送                   | 展示准确提交，确认后才放行         |
| 基础推送   | 首次推送新分支                   | 正确识别新远端 ref，不误列全量历史 |
| 多引用     | 一次推送多个分支                 | 每个 ref 均被解析与展示            |
| 删除       | 删除远端分支                     | 单独显示删除风险                   |
| 强制推送   | `--force` / `--force-with-lease` | 正确识别风险，仍绑定本次请求       |
| 用户拒绝   | 取消 / 关闭窗口                  | push 失败，远端 ref 未变化         |
| 输入校验   | 输入 `y` 或其它文本              | 不确认，不放行                     |
| 超时       | 超过配置有效期                   | 请求失效，push 失败                |
| 应用状态   | 桌面端未启动                     | 无控制终端时退出码 7，远端不变     |
| IPC        | 超时、断开、响应非法             | 拒绝，远端不变                     |
| 并发       | 两个仓库同时推送                 | 请求隔离，不串单                   |
| 重放       | 重复 / 迟到 / 伪造响应           | 拒绝                               |
| 上下文变化 | 确认期间 ref 或 remote 变化      | 旧确认失效，远端不变               |
| Hook 冲突  | 仓库已有 Hook / 备份已存在       | 不静默覆盖                         |
| 路径       | worktree、自定义 `hooksPath`     | 按设计处理或明确拒绝               |
| 跨平台     | macOS / Linux（Windows 待实现）  | 各平台独立通过核心测试             |

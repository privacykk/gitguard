# 安全边界与限制（Week 1）

## 当前保证

- 未知、非法或不可判断情况采用 fail-closed；只有显式 `allow` 返回 0。
- `RequireConfirmation` 在确认机制缺失时拒绝。
- CLI 完整读取并解析全部 stdin，任意非法 ref 都会拒绝整个请求。
- 测试中的外部 Git 调用使用可执行文件和参数数组，不把 ref、remote、URL 或 Git 配置拼接成 shell 命令。
- 原型不访问云端业务服务，不包含遥测、自动同步或凭据处理，不记录 Token、私钥或环境变量。
- 真实 Git 集成测试只使用临时本地仓库与 bare remote，并隔离全局和系统 Git 配置。
- 不提供自动 Hook 安装，因此不会静默覆盖已有 Hook。

## 明确不属于当前保证

- 本机管理员可以删除、替换或绕过 Hook；GitGuard 不声称抵御拥有完整本机控制权的用户。
- 显式 `allow` 仅用于验证允许路径，不是经过用户配置和优先级计算的正式策略。
- 尚未验证多 push URL、`pushurl`、URL rewrite、直接 URL 或所有 Git 版本差异。
- 尚无 IPC 身份认证、请求绑定、超时、一次性批准、过期机制及后台服务崩溃的完整验证。
- 尚无 Hook 安装、升级、卸载、备份与恢复；手工安装前必须检查已有文件。
- 尚无 Windows 的真实 shell Hook 集成测试；macOS/Linux 之外的实际桌面环境也未完成验收。
- 尚无系统凭据库、日志脱敏设施、数据导出或审计功能。

## 后续安全任务

正式 IPC、确认 UI、一次性批准及过期机制、服务异常 fail-closed 验证、Hook 生命周期管理、多 remote 边界、三平台真实环境测试、系统凭据库与日志脱敏必须保留在后续路线图中。
